# PMI / AI Governance Mapping

This map shows how the portfolio design represents project-governance principles; it is not PMI certification of the implementation.

| Governance concern | Attestor implementation/evidence |
| --- | --- |
| Value / benefits | outcome assurance is framed around evidence-supported customer outcomes, not AI activity |
| Governance | deterministic decision envelope, versioned module boundaries and human approval |
| Stakeholder accountability | CSM/Admin/approver/system responsibilities remain distinct |
| Risk | risk, defect, decision and failure-mode registers are maintained |
| Human oversight | consequential actions require human authority; adversarial tests include approval mismatch/reuse |
| Predictive/adaptive fit | deterministic controls own governed decisions; AI narrative is bounded and advisory |
| Decision authority | AI cannot approve itself or override deterministic policy |
| Transparency | evidence index, reports, test IDs and limitation statements trace claims |
| Responsible AI | security mapping distinguishes tested controls from documented-but-unproven production controls |

See [PMP Governance](pmp-governance.md), [Decision Register](decision-register.md), [Risk Register](risk-register.md), and [OWASP AI Security Mapping](OWASP_AI_SECURITY_MAPPING.md).
